<div class="custom-tag-yellow">Atelier Pratique</div>

Aujourd'hui, on joue... et on triche! 

**Paperclips** est un petit jeu console inspiré de [Universal Paperclips](https://www.decisionproblem.com/paperclips/) de Frank Lantz: vous êtes une IA dont le seul but est de fabriquer des trombones. Le jeu sauvegarde votre progression dans un fichier, et il offre même de **chiffrer la sauvegarde avec AES** pour empêcher la triche.

Votre mission: vous donner 1 000 000 $ dans le jeu, d'abord sans chiffrement, puis avec.

Cet atelier réutilise tout ce qu'on a vu depuis le début du bloc:
- **Process Monitor** pour trouver un fichier (3.2)
- **la décompilation** pour lire le code d'un exécutable .NET (3.1)
- **AES** avec une clé et un vecteur d'initialisation (3.4)

:::info Le message à retenir
Tout ce qui est installé chez l'utilisateur (l'exécutable, ses fichiers, ses clés) peut être lu et modifié par l'utilisateur. On ne peut pas faire confiance au client.
:::


## Préparation

- Le **runtime .NET 8** doit être installé sur votre poste (déjà fait au cégep)
- Téléchargez le jeu: [PaperclipsConsole.exe](https://github.com/departement-info-cem/3s4-cybersec/releases/latest/download/PaperclipsConsole.exe)
- Ayez sous la main **Process Monitor** (3.2) et **ILSpy** ou **dotPeek** (3.1)
- Ouvrez [CyberChef](https://gchq.github.io/CyberChef/) dans votre navigateur

Prenez des notes et des captures d'écran au fur et à mesure: elles serviront à vos remises CTF.


## Déroulement (environ 2 h)

| Étape | Durée | Objectif |
|---|---|---|
| 1. Découvrir le jeu | 10 min | Comprendre ce qu'on veut modifier |
| 2. Trouver la sauvegarde | 15 min | Localiser le fichier avec Process Monitor |
| 3. Tricher sans chiffrement | 10 min | Modifier la sauvegarde en clair |
| 4. Activer le chiffrement | 5 min | Constater que le fichier devient illisible |
| 5. Décompiler le jeu | 25 min | Trouver la clé et comprendre où est l'IV |
| 6. Déchiffrer la sauvegarde | 35 min | Lire et modifier la sauvegarde chiffrée |
| Discussion | 15 min | Qu'est-ce qui aurait protégé le jeu? |


## Étape 1 : Découvrir le jeu

Lancez `PaperclipsConsole.exe`, choisissez **Nouvelle partie** et jouez quelques minutes.

Touches utiles:
- **P** : fabriquer un trombone
- **W** : acheter du fil (*wire*)
- **A** : acheter un AutoClipper
- **+** / **-** : changer le prix de vente
- **S** : sauvegarder
- **Q** : quitter

Repérez les valeurs qu'un tricheur voudrait modifier: les fonds (`$`), le fil, les trombones...


## Étape 2 : Trouver la sauvegarde

Le jeu sauvegarde quelque part sur votre disque, mais où?

1. Démarrez **Process Monitor** et ajoutez un filtre `Process Name` `is` `PaperclipsConsole.exe`
2. Dans le jeu, appuyez sur **S** pour forcer une sauvegarde
3. Arrêtez la capture et cherchez les opérations `WriteFile`

**Question**: Quel est le chemin complet du fichier de sauvegarde? Pourquoi un développeur choisirait-il ce dossier?


## Étape 3 : Tricher sans chiffrement

1. **Quittez le jeu** (touche **Q**)
2. Ouvrez la sauvegarde dans un éditeur de texte
3. Donnez-vous 1 000 000 $
4. Relancez le jeu et choisissez **Continuer la partie**

:::warning Fermez le jeu avant de modifier la sauvegarde
Le jeu sauvegarde automatiquement toutes les 30 secondes. S'il est ouvert pendant que vous modifiez le fichier, il va écraser votre modification.
:::

**Question**: En quoi le format du fichier vous a-t-il aidé?


## Étape 4 : Activer le chiffrement

1. Au menu de départ, activez **Chiffrement Sauvegarde**
2. Commencez une nouvelle partie, jouez un peu, sauvegardez (**S**) et quittez (**Q**)
3. Ouvrez la sauvegarde dans un éditeur de texte

**Question**: Que voyez-vous? Pouvez-vous encore tricher comme à l'étape 3?

:::tip Si vous abîmez la sauvegarde
Si le jeu n'arrive pas à lire la sauvegarde, il affiche un message, garde une copie du fichier invalide (`data.json.invalide`) et crée une nouvelle partie.
:::


## Étape 5 : Décompiler le jeu

Ouvrez `PaperclipsConsole.exe` dans **ILSpy** ou **dotPeek**.

1. Trouvez la classe qui gère la sauvegarde et le chargement
2. Trouvez les méthodes qui chiffrent et déchiffrent
3. Notez tous les paramètres nécessaires pour déchiffrer:
   - L'algorithme et le mode de chiffrement
   - La clé (attention: elle est déclarée en **octets**, pas en texte)
   - D'où vient l'IV, et où il se retrouve dans le fichier

**Question**: Le code déclare une variable pour l'IV. Est-elle vraiment utilisée? Lisez attentivement la méthode de chiffrement.

:::info Comparez avec JeanLouisEtFils (3.4)
Le principe est le même que dans JeanLouisEtFils: un IV aléatoire placé devant les données chiffrées. Par contre, la sauvegarde est écrite en **octets bruts**, pas en Base64.
:::


## Étape 6 : Déchiffrer la sauvegarde

Dans CyberChef:

1. Ouvrez la sauvegarde chiffrée comme entrée (bouton *Open file as input*)
2. Ajoutez la recette **To Hex** pour voir le contenu: notez les **32 premiers caractères**, c'est l'IV
3. Remplacez la recette par:
   - **Drop bytes** (Start: `0`, Length: `16`) pour retirer l'IV
   - **AES Decrypt** avec la clé en **HEX**, l'IV en **HEX**, le mode **CBC**, Input **Raw** et Output **Raw**
4. Vous devriez voir apparaître le JSON de la sauvegarde

Modifiez maintenant vos fonds et remettez la sauvegarde en place pour que le jeu l'accepte.

**Question**: Devez-vous vraiment rechiffrer le fichier? Relisez la méthode qui **charge** la sauvegarde dans le code décompilé.


## Discussion : qu'est-ce qui aurait protégé le jeu?

En équipe, répondez aux questions suivantes:
- Le chiffrement AES était-il mal choisi? Où était le vrai problème?
- Est-ce que cacher la clé dans le code (obfuscation, clé découpée en morceaux...) aurait changé quelque chose?
- Le chiffrement protège la **confidentialité**. Protège-t-il l'**intégrité** de la sauvegarde?
- Si vous étiez le développeur d'un jeu en ligne avec un classement, où garderiez-vous les fonds des joueurs?
- Faites le lien avec le TP3: l'application se rabat sur une **BD locale** quand le serveur n'est pas disponible. Pourquoi est-ce un problème?

## 🚩 CTF-paperclips-clair (1 point)

📄 **Fichier de remise**: `ctf-paperclips.md`

**Objectif**: Avoir au moins 1 000 000 $ dans une partie **sans chiffrement**.

**À inclure dans votre remise**:
- Le chemin de la sauvegarde et comment vous l'avez trouvé (capture de Process Monitor)
- Une capture du jeu avec vos fonds

---

## 🚩 CTF-paperclips-cle (2 points)

📄 **Fichier de remise**: `ctf-paperclips.md`

**Objectif**: Extraire de l'exécutable tous les paramètres du chiffrement de la sauvegarde.

**À inclure dans votre remise**:
- L'algorithme et le mode de chiffrement
- La clé en hexadécimal
- D'où vient l'IV et où il est stocké
- Une capture du code décompilé

📄 **Fichier de remise**: `ctf-paperclips.md`

**Objectif**: Déchiffrer une sauvegarde chiffrée.

**À inclure dans votre remise**:
- Une capture de la recette CyberChef
- Le JSON déchiffré

---

## 🚩 CTF-paperclips-raccourci (2 points)

📄 **Fichier de remise**: `ctf-paperclips.md`

**Objectif**: Avoir au moins 1 000 000 $ dans une partie où le chiffrement est **activé**, sans rechiffrer la sauvegarde.

**À inclure dans votre remise**:
- Une capture du jeu avec vos fonds et le chiffrement activé
- L'extrait du code décompilé qui explique pourquoi ça fonctionne

---

## 🚩 CTF-paperclips-rechiffre (3 points)

📄 **Fichier de remise**: `ctf-paperclips.md`

**Objectif**: Produire une sauvegarde **chiffrée** valide (le fichier doit rester illisible dans un éditeur de texte) qui vous donne au moins 1 000 000 $.

:::tip Indices
- Le jeu génère un nouvel IV à chaque sauvegarde. Vous pouvez choisir le vôtre.
- Dans CyberChef, la recette **AES Encrypt** peut produire du HEX. Il restera à placer l'IV au bon endroit, puis à revenir en octets bruts (**From Hex**) et à enregistrer le résultat.
:::

**À inclure dans votre remise**:
- La recette utilisée
- Une capture de la sauvegarde ouverte dans un éditeur de texte (illisible)
- Une capture du jeu avec vos fonds
