Nous te fournissons une [application C#](https://github.com/departement-info-cem/3U4-TP3/releases/latest) qui :
- implante le hachage de mot de passe et le chiffrement
- permet de rentrer ses revenus de l'année
- permet de calculer des impôts à payer pour chaque année

Toutefois, nous allons voir que c'est fait plus ou moins bien. Ton but va être de corriger:
- le hachage qui a été choisi
- la technique de chiffrement

Finalement, nous allons voir que l'application est exposée aux injections SQL. Ici aussi tu devras corriger.

## Format de remise

Tu vas recevoir un lien GitHub Classroom pour remettre ton travail. Tu devras remettre:
1. un fichier **rapport.md** où tu expliqueras 
  - les différentes attaques
  - les solutions que tu as implantées avec la preuve que l'attaque ne fonctionne plus
2. une version modifiée et corrigée de l'application (projet avec le code source) qui corrige les failles identifiées 
  - IMPORTANT : si tu ne remets pas le projet corrigé, tu auras 0 sur les correctifs.
  - IMPORTANT : si l'application remise n'est plus fonctionnelle, tu auras 0 sur les correctifs.

## Vérification post correctifs

Tu dois t'assurer que ton application fonctionne toujours. Tu peux par exemple vérifier la séquence suivante:
1. te créer un compte
2. t'ajouter une année de revenu
3. arrêter l'application
4. redémarrer l'application
5. te connecter avec ton compte
6. regarder tes revenus
7. vérifier ton profil, tous les champs

:::info Repartir avec une BD propre
Les comptes déjà présents dans la BD ont été créés avec l'ancien hachage et l'ancien chiffrement: ton application corrigée ne pourra pas les lire. Tu n'as pas à les migrer. Après chaque correctif:
1. supprime le fichier de la BD locale
2. relance l'application
3. recharge les comptes avec l'option « Les premiers ministres »

C'est aussi à partir de cette nouvelle BD que tu dois démontrer que l'attaque ne fonctionne plus.
:::

## La fuite de la base de données

Normalement, l'application utilise un serveur de base de données sécurisé pour stocker les informations.

Cependant, l'application se rabat sur une BD locale si le serveur n'est pas disponible.

Cela va te permettre d'accéder à la base de données et d'essayer d'accéder au maximum d'informations possible.

En utilisant des techniques vues en cours, il faut que 
- tu détermines où le .exe stocke la BD locale
- tu explores le contenu de la BD locale

Pour cette étape préalable, tu as le droit d'utiliser `consoleApp.exe` (l'exécuter, le décompiler, surveiller ses accès aux fichiers).

Une fois la BD trouvée, tu la charges avec les « premiers ministres » et tu en fais une copie: c'est ta **BD fuitée**. Les attaques 1 et 2 se font uniquement à partir de cette copie.

:::note « Accès BD après exécution »
Dans les tableaux ci-dessous, cela veut dire que tu ne peux pas te servir de l'application pour obtenir de l'information supplémentaire dans la BD. Par exemple, tu ne peux pas créer un compte avec un mot de passe connu puis comparer son hash à ceux des premiers ministres. Un vrai pirate qui a volé la BD n'aurait pas cette possibilité.
:::

## Barème

### 1. Hachage

Retrouve les mots de passe de plusieurs utilisateurs:

| Point de départ | Permis | Interdit                                                        |
| -- | -- |-----------------------------------------------------------------|
| BD *fuitée* après avoir chargé les « premiers ministres ». | Accès à la BD fuitée (fichier) <br/> Outils de craquage | Code source <br/> consoleApp.exe <br/> Accès BD après exécution |

Tu dois ensuite implanter le hachage avec bcrypt et montrer que l'attaque ne fonctionne plus. Vérifie que l'application fonctionne.

**2 points** pour l'attaque sur les mots de passe dans le rapport avec toutes les étapes et captures d'écran

**4 points** pour le correctif implanté via 
- une modification au code source (commit)
- une démonstration que l'attaque ne fonctionne plus dans le rapport avec toutes les étapes et captures d'écran

### 2. Chiffrement

Actuellement le NAS est «sécurisé» par une méthode de chiffrement. Tu dois chercher une méthode pour décrypter les NAS des comptes des premiers ministres.

| Point de départ | Permis | Interdit                                                        |
| -- | -- |-----------------------------------------------------------------|
| BD *fuitée* après avoir chargé les « premiers ministres ». | Accès à la BD fuitée (fichier) <br/> consoleApp.exe (décompilation) <br/> Outils de craquage | Code source <br/> Accès BD après exécution |

:::tip
Tu n'as pas accès au code source, mais rien n'empêche un pirate de décompiler le .exe. Revois les cours [3.1](/cours/r3.1) et [3.4](/cours/r3.4).
:::

Tu devras implanter AES dans l'application et montrer que ton attaque ne fonctionne plus. Vérifie que l'application fonctionne.

Pour que le correctif soit accepté:
- l'**IV doit être aléatoire** et différent pour chaque valeur chiffrée (il peut être stocké en clair avec le texte chiffré)
- la **clé ne doit pas être codée en dur** dans le code source. Explique dans ton rapport où tu la stockes et pourquoi (par exemple: variable d'environnement, fichier hors du dépôt, DPAPI).

**2 points** pour l'attaque sur le chiffrement dans le rapport avec toutes les étapes et captures d'écran

**4 points** pour le correctif du chiffrement 
- une modification au code source (commit)
- une démonstration que l'attaque ne fonctionne plus dans le rapport avec toutes les étapes et captures d'écran, **y compris en décompilant ta version corrigée**

### 3. Injection SQL

L'application a au moins un point de vulnérabilité à une injection SQL.

Les attaques par injection SQL se font sur la **version originale** de l'application (le `consoleApp.exe` fourni), et non sur ta version corrigée.

| Point de départ                                         | Permis                                                           | Interdit                                                       |
|---------------------------------------------------------|------------------------------------------------------------------|----------------------------------------------------------------|
| Accès à consoleApp.exe (version originale) <br/> Premiers ministres chargés | consoleApp.exe | Code source <br/>  Accès BD |

Tu devras éliminer les points d'injection SQL dans l'application.

**1 point** Démonstration d'une attaque par injection SQL. Si tu démontres une attaque qui exécute
n'importe quelle commande SQL, tu gagnes un point avec les commandes et captures d'écran.

**1 point** Si tu arrives à changer le mot de passe de Justin Trudeau, tu gagnes un point en plus. 
Démontre l'attaque en entrant dans le compte de Justin Trudeau via l'application. Commandes et captures d'écran.

**4 points** pour le correctif de toutes les injections SQL possibles 
- une modification au code source (commit)
- une démonstration, sur ta version corrigée, que l'attaque ne fonctionne plus dans le rapport avec toutes les étapes et captures d'écran

### Qualité du français (2 points)

Le français est correct (utiliser le correcteur de Word avec Antidote au minimum)
